# DeepPCB With Misalignment (COEN 6314 project)

[DeepPCB](https://github.com/tangsanli5201/DeepPCB/tree/master) is a supervised **object-detection** dataset: each
PCB defect must be located (bounding-box **regression**) and labelled with one of six classes (**classification**:
open, short, mousebite, spur, spurious copper, pin-hole). This folder adds **controlled misalignment** to it, so we
can test whether a compact learned detector (**YOLOv10-Nano**, trained with and without shift augmentation) tells
real defects from the false differences that misalignment creates, compared with a non-learned
**registration-and-differencing** baseline.

Everything here is generated by the scripts in `scripts/` from the untouched DeepPCB download.
Seed: **6314** (per pair: `np.random.default_rng([6314, pair_id])`, so results don't depend on file order).
The two-page data report is `report/data_report_v2.pdf` (black-and-white version: `report/data_report_bw.pdf`).

## Key numbers
| | |
|---|---|
| Image pairs (template + inspected, 640 × 640) | 1,500 |
| Defect boxes | 10,013 (1–15 per pair, median 35 × 33 px) |
| Split (train / val / test) | 800 / 200 / 500, grouped by board |
| Misalignment conditions (val + test) | 10: as supplied, 1/2/3/5 px in x or y, residual (0.25–1.5 px + ≤ 0.5°) |

| Pairs already misaligned in DeepPCB | 123 (8.2 %) |
| Verification checks passed | 9 / 9 |

## Rebuild
```bash
bash scripts/run_all.sh
```
Needs Python 3 with `numpy`, `opencv-python` and `Pillow`. The raw data are expected at
`../DeepPCB-master/DeepPCB-master/PCBData` (the layout of DeepPCB's zip download, unpacked next to this folder).
If you cloned DeepPCB instead, point the script at its `PCBData` folder:
```bash
PCB_ROOT=/path/to/DeepPCB/PCBData bash scripts/run_all.sh
``` `sets/` and the YOLO export (`yolo/`, ~1 GB) are not stored in git because of GitHub's file-size
limits; `run_all.sh` recreates them.

### What the CSV files record
These are annotations and metadata for splitting, evaluation and error analysis; the detector's input features
are the image pixels themselves.

| File | One row per | Columns |
|---|---|---|
| `pairs.csv` | source pair (1,500) | `pair_id, group, temp, test, label, official_split, temp_channels, test_channels, n_boxes` |
| `boxes.csv` | original box (10,013) | `pair_id, group, official_split, x1, y1, x2, y2, cls, cls_name, w, h` |
| `splits.csv` | source pair (1,500) | `pair_id, group, official_split, split, temp, test, label, n_boxes, native_dx, native_dy, native_misaligned, test_has_trainval_duplicate` |
| `images.csv` | inspected image (7,800) | `image_id, pair_id, group, split, condition, ref_path, inspected_path, dx, dy, rot_deg, shift_mag, native_dx, native_dy, native_misaligned, test_has_trainval_duplicate, n_boxes, n_ignored` |
| `labels.csv` | box per image (52,088) | `image_id, pair_id, split, condition, x1, y1, x2, y2, cls, ignore` |

Classes `cls` 1–6 = open, short, mousebite, spur, copper, pin-hole (DeepPCB numbering; YOLO uses 0–5).
**Why COCO as well:** it is the standard detection format, read directly by torchvision, Detectron2 and
MMDetection (so Fast R-CNN or SSD can be swapped in without re-exporting), and its `iscrowd` flag lets
`pycocotools` treat ignore boxes as don't-care regions.

### Conditions
`s0` (as given), `s1x s1y s2x s2y s3x s3y s5x s5y` (1/2/3/5 px along x or y, sign drawn per pair),
`r` (residual: sub-pixel translation 0.25–1.5 px in a random direction + rotation in ±0.5°).
Val and test have all 10 conditions (200 × 10, 500 × 10 images); train stores `s0` only (800) and gets its
misalignment from augmentation (see YOLO export below).

## How each ProposalV4 requirement was implemented
- **Official split kept**: 1000 trainval / 500 test.
- **~20 % validation, grouped by board, before augmentation**: DeepPCB has no board ID, so its group folder is the
  board unit and all images of a group stay together. All subsets of trainval groups with 17–23 % of pairs were
  scored by L1 distance of class proportions to trainval; best = **group00041 (200 pairs)** → train 800 / val 200 /
  test 500. Runner-up: groups 44000+50600+77000 (L1 0.068 vs 0.059). No group is shared by train and val, and every
  shifted variant of a pair stays in its pair's split.
- **Cross-partition near-duplicates checked**: dHash on all 1500 templates → 337 candidates → pixel-level check
  (best ±8 px shift, Jaccard ≥ 0.9 on both copper and background, near-blank templates excluded).
  40 confirmed duplicates, **all within one group** (supports group as the board unit); none cross train/val.
  3 test pairs duplicate a train pair (`50600065`, `92000114`, `92000118`) → flagged `test_has_trainval_duplicate`
  so you can report test results with and without them.
- **Controlled shifts**: reference fixed; inspected image and its boxes moved together. Integer shifts are pixel-exact
  (no interpolation). Identical seeded shifts for every method — both read the same files.
- **Residual set**: bilinear warp, one variant per val/test pair; recorded parameters verified with ECC
  (max corner error 0.05 px on 120 samples).
- **Padded borders excluded**: uncovered pixels are edge-replicated and lie inside an **8 px border** that evaluation
  must ignore (valid region x,y ∈ [8, 632]); discard predictions centred there too.
- **Boundary-truncated defects ignored consistently**: a box is `ignore=1` in *every* condition if its original box is
  within 14 px (8 border + 6 max displacement) of an edge — 258 of 10 013 boxes (2.6 %). Treat them as don't-care
  (not TP, not FN; a prediction matching one is not an FP).
- **Labels checked**: automatic — 5600/5600 integer images pixel-exact, 36 640/36 640 box contents identical after shift,
  41 220/41 220 non-ignored boxes inside the valid region; visual — `qa/check_*.png`.

## Verification
Two independent checks: the pipeline's own QA scripts (`06`, `09`) and a separate audit that re-decodes the raw
DeepPCB files with a different library (Pillow/SciPy instead of OpenCV) and shares no pipeline code. All pair
lists, splits, labels, integer shifts (5600/5600), residual images (700/700), COCO files (21/21) and YOLO images
(10 200/10 200) agree. The only difference is one colour JPEG (`44000020`) whose grey conversion differs between
decoders; its shifted copies still match its own `s0` exactly.

## Findings that affect the experiment
1. **Some "aligned" pairs are not aligned.** 123/1500 pairs (75 train, 8 val, 40 test) have a native integer offset
   (mostly 2–3 px, up to 8 px) that reduces the reference/inspected XOR by ≥ 1.5× — see `qa/native_misalignment_examples.png`.
   Their `s0` is already misaligned, and a controlled shift adds to it (`native_dx/dy` columns let you compute the
   effective offset). Suggested: report the main curves on the 1377 clean pairs (460 test) and the full set as a
   sensitivity check. The non-augmented training run therefore also sees some misalignment.
2. **Test shares some boards with training.** Keeping the official test list means 168/500 test pairs come from 7
   groups also in trainval (21 from the validation group); the other 332 come from 4 groups never seen in training
   (12000, 12100, 12300, 90100). Report test results on all 500, on the 332 unseen-board pairs, and without the
   3 duplicates — similar numbers show leakage is not inflating them.
3. **Misalignment multiplies false differences.** Outside the labelled boxes, pixels differing from the template
   rise from 1.8 % of the image as supplied to 2.2 / 3.2 / 4.3 / 6.7 % at 1 / 2 / 3 / 5 px (2.7 % residual),
   i.e. from 6× to 16× the defect pixels (`reports/false_difference.json`).
4. 62 original images (in 57 pairs) are 3-channel JPEGs; all outputs are single-channel PNGs (lossless, so shifted
   images contain no new JPEG artefacts that would differ from the reference).
5. 17 templates are near-blank (< 2 % copper or background). Most defects in DeepPCB are synthetic.

## YOLOv10-N export (scripts 08–09)
Written to `yolo/` by `run_all.sh` (not stored in git).
Each pair is one **3-channel PNG**: channel 0 = reference, 1 = inspected, 2 = |reference − inspected|
(so the RGB-pretrained `yolov10n.pt` can be used unchanged). Labels are YOLO `.txt` (`class xc yc w h`,
classes 0–5 = open, short, mousebite, spur, copper, pin-hole).

| Subset | Contents | Needed for |
|---|---|---|
| `train_noaug` (800), `train_aug` (2400), `val_s0` (200), `data_noaug.yaml`, `data_aug.yaml` | training images and dataset files | training both runs |
| `val_<cond>` | val, all shifted conditions + residual | threshold checks / analysis on val |
| `test_<cond>` | test, all 10 conditions | the single final test evaluation |

- `train_aug` = each train pair 3×: original, one integer shift (1–5 px, random axis/sign), one residual
  (sub-pixel + ≤0.5° rotation); exact transforms in `train_aug_transforms.csv`; own seed stream, independent of
  the evaluation sets. **Train the aug run for 1/3 of the no-aug epochs** so both runs take the same number of steps.
- **Keep colour augmentation off** (`hsv_h=hsv_s=hsv_v=0` in Ultralytics): it would change the three channels
  differently and corrupt the difference channel. Translate/scale/flip move all channels together and are safe.
- **All boxes are written, including `ignore` ones** (YOLO has no ignore concept; dropping a visible defect
  would teach "background"). Apply the ignore rule in your own evaluation from `index/labels.csv`.
- Checks (`reports/yolo_check.json`): 10 200/10 200 labels present, counts and classes match, channels exact,
  coordinates exact except 50 ignore-flagged boxes clipped at the image edge (correct); 17 of 5338 augmented
  boxes lie within 5 px of the edge and are partly shifted off-image (correct). Visual: `qa/yolo_check.png`.
