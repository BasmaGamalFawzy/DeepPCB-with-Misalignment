# DeepPCB with Misalignment (COEN 6314 project)

Everything here is generated by the scripts in `scripts/` from the untouched [DeepPCB](https://github.com/tangsanli5201/DeepPCB/tree/master). 
Rebuild with `bash scripts/run_all.sh` (Python 3, numpy, opencv, Pillow).
Seed: **6314** (per pair: `np.random.default_rng([6314, pair_id])`, so results don't depend on file order).

If you cloned DeepPCB (instead of downloading its zip), point the script at its data:
`PCB_ROOT=/path/to/DeepPCB/PCBData bash scripts/run_all.sh`

`sets/` and the `yolo_*.zip` files are not stored in git (the zips exceed GitHub's 100 MB file limit). For `sets/` you can rebuild it with `run_all.sh`. For `yolo_*.zip` files you can download them [here](https://drive.google.com/drive/folders/1YbJ-ykGt-YbIVZ7kgXPAec6kDwmX0AEO?usp=sharing)

## Folder layout
| Path | What it is |
|---|---|
| `sets/ref/<pair>.png` | reference (template) image, grayscale PNG, never transformed |
| `sets/<split>/<cond>/<pair>.png` | inspected image after the transform for that condition |
| `index/splits.csv` | one row per pair: train / val / test, group, native-misalignment and duplicate flags |
| `index/images.csv` | one row per inspected image: split, condition, dx, dy, rot_deg, paths |
| `index/labels.csv` | one row per box per image (transformed coords), class, `ignore` flag |
| `index/coco/<split>_<cond>.json` | same data in COCO format (`ignore` → `iscrowd=1`; `ref_file` gives the reference) |
| `index/original_pair_alignment.csv` | integer offset audit of every original pair |
| `index/near_duplicates_*.csv` | duplicate scan (hash candidates → pixel-level confirmation) |
| `reports/*.json` | numbers behind every statement below |
| `qa/check_<cond>.png` | visual label checks: reference · s0+boxes · transformed+boxes · \|ref − transformed\| |
| `scripts/pcb_shift.py` | the transform code, reusable for on-the-fly shift augmentation (`random_train_shift`) |

Conditions: `s0` (as given), `s1x s1y s2x s2y s3x s3y s5x s5y` (1/2/3/5 px along x or y, sign drawn per pair),
`r` (residual: sub-pixel translation 0.25–1.5 px in a random direction + rotation in ±0.5°).
Val and test have all 10 conditions (200 × 10, 500 × 10 images); train has `s0` only (800); its shifted copies are in train_aug (see YOLO section).

## How each requirement was implemented
- **Official split kept**: 1000 trainval / 500 test.
- **~20 % validation, grouped, before augmentation**: unit = DeepPCB group folder (the only source-board ID).
  All subsets of trainval groups with 17–23 % of pairs were scored by L1 distance of class proportions to trainval;
  best = **group00041 (200 pairs)** → train 800 / val 200 / test 500. Runner-up: groups 44000+50600+77000 (L1 0.068 vs 0.059).
  Every shifted variant of a pair stays in its pair's split.
- **Cross-partition near-duplicates checked**: dHash on all 1500 templates → 337 candidates → pixel-level check
  (best ±8 px shift, Jaccard ≥ 0.9 on both copper and background, near-blank templates excluded).
  40 confirmed duplicates, **all within one group** (supports group as the board unit); none cross train/val.
  3 test pairs duplicate a train pair (`50600065`, `92000114`, `92000118`) → flagged `test_has_trainval_duplicate`
  so you can report test results with and without them.
- **Controlled shifts**: reference fixed; inspected image and its boxes moved together. Integer shifts are pixel-exact
  (no interpolation). Identical seeded shifts for every method — both read the same files.
- **Residual set**: bilinear warp, one variant per val/test pair; recorded parameters verified with ECC
  (max corner error 0.05 px on 120 samples).
- **Padded borders excluded**: uncovered pixels are edge-replicated and lie inside an **8 px border** that evaluation
  must ignore (valid region x,y ∈ [8, 632]); discard predictions centred there too.
- **Boundary-truncated defects ignored consistently**: a box is `ignore=1` in *every* condition if its original box is
  within 14 px (8 border + 6 max displacement) of an edge — 258 of 10 013 boxes (2.6 %). Treat them as don't-care
  (not TP, not FN; a prediction matching one is not an FP).
- **Labels checked**: automatic — 5600/5600 integer images pixel-exact, 36 640/36 640 box contents identical after shift,
  41 220/41 220 non-ignored boxes inside the valid region; visual — `qa/check_*.png`.

## Findings that affect the experiment
1. **Some "aligned" pairs are not aligned.** 123/1500 pairs (75 train, 8 val, 40 test) have a native integer offset
   (mostly 2–3 px, up to 8 px) that reduces the reference/inspected XOR by ≥ 1.5× — see `qa/native_misalignment_examples.png`.
   Their `s0` is already misaligned, and a controlled shift adds to it (`native_dx/dy` columns let you compute the
   effective offset). Suggested: report the main curves on the 1377 clean pairs and the full set as a sensitivity check.
2. **Test boards are mostly unseen**: 332/500 test pairs come from 4 groups absent from trainval
   (12000, 12100, 12300, 90100) — a group-held-out validation set mirrors this well.
3. 62 original images (in 57 pairs) are 3-channel JPEGs; all outputs are single-channel PNGs (lossless, so shifted images contain
   no new JPEG artefacts that would differ from the reference).
4. 17 templates are near-blank (< 2 % copper or background).

## YOLOv10-N export (scripts 08–09)
Each pair is one **3-channel PNG** holding the reference, the inspected image and |reference − inspected|, so the RGB-pretrained `yolov10n.pt` can be used unchanged. The PNG is written with OpenCV, so in the file's color order blue = reference, green = inspected and red = difference. Loaders that use RGB order (Pillow, and Ultralytics when it feeds the network) see the channels reversed. This does not affect training, but keep it in mind when inspecting or reusing the images.

Labels are YOLO `.txt` files, one line per box (`class xc yc w h`, normalised to 0–1),
with classes 0–5 = open, short, mousebite, spur, copper, pin-hole.

| Zip | Contents | Needed for |
|---|---|---|
| `yolo_train.zip`  | `train_noaug` (800), `train_aug` (2400), `val_s0` (200), `data_noaug.yaml`, `data_aug.yaml` | training both runs |
| `yolo_eval_val.zip` | val, all shifted conditions + residual | threshold checks / analysis on val |
| `yolo_eval_test_a.zip`, `_b.zip` | test, all 10 conditions | the single final test evaluation |

- `train_aug` = each train pair 3×: original, one integer shift (1–5 px, random axis/sign), one residual
  (sub-pixel + ≤0.5° rotation); exact transforms in `train_aug_transforms.csv`; own seed stream, independent of
  the evaluation sets. **Train the aug run for 1/3 of the no-aug epochs** so both runs take the same number of steps.
- **All boxes are written, including `ignore` ones** (YOLO has no ignore concept; dropping a visible defect
  would teach "background"). Apply the ignore rule in your own evaluation from `index/labels.csv`.
- Checks (`reports/yolo_check.json`): 10 200/10 200 labels present, counts and classes match, channels exact,
  coordinates exact except 50 ignore-flagged boxes clipped at the image edge (correct); 17 of 5338 augmented
  boxes lie within 5 px of the edge and are partly shifted off-image (correct). Visual: `qa/yolo_check.png`.
